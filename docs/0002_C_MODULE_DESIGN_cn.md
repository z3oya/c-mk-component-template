# 0002 C 模块设计文档规范

C 模块设计文档必须包含以下六节。

## 写作规则

- 每个事实只陈述一次，写在归属章节。
- 使用约束只出现在接口详情；共享类型映射、参数格式与全局返回值只出现在对外数据结构。
- 不写括注式说明：有信息量的括注改写进句子或移动到归属章节。
- 不写判定顺序、设计动机等过程性或论证性叙述。
- 不使用 emoji 或组合式 Unicode。

## 1. 对外数据结构

- 模块不导出任何公开数据结构时，在此显式声明。
- 多个接口共用的约定在此定义：类型映射、参数格式与全局约定的返回值。
- 全局返回值：一张只含码与含义的表。哪些接口产生哪些码在接口条目中写明，不写入表中。
- 每个导出的 struct/enum/union 须用 ```c 围栏代码块展示完整代码定义。
- 每个导出的 struct/enum/union 一条：用途与字段表，含名称、单位/取值范围、说明。
- 指针字段须注明内存归属方及其生命周期。

## 2. 对外接口一览表

- 一张表列出全部对外函数：签名与用途短语。
- 说明列只写用途。行为、返回值、所有权与约束属于第 3 节，不得出现在本表。

## 3. 对外接口详情

- 不设通用约定等汇总性小节。每条使用约束写入其适用接口的条目。
- 每个函数须说明：

  - 参数检查条件：前置条件及非法输入时的行为，以返回值、断言或忽略处理。
  - 数据生命周期：由谁分配与释放、数据有效时长。
  - 输入输出行为：每类已定义输入对应的可观察结果；作为测试用例的依据。
  - 线程安全：锁机制与调用者义务。

- 多个条目共用的术语在首次使用的条目内定义。
- 一个条目内的多个条件或输入类别写成 `-` 子条目，每类一条；仅一条时直接写在条目行上。

示例：

````markdown
### `circ_push`

```c
int circ_push(circ_t *c, const void *item);
```

- 参数检查条件：
  - `c == NULL` 返回 -1。
  - `item == NULL` 返回 -1。
- 数据生命周期：`item` 被拷贝入内部缓冲区，调用返回后调用者即可复用其内存。
- 输入输出行为：
  - 有空位：存入消息，返回 0。
  - 缓冲区已满：返回 -1，缓冲区保持不变。
- 线程安全：同一实例上的并发调用由内部锁串行化。
````

## 4. 典型用例

- 每条主要工作流给出一个最小可编译示例。
- 示例以 main 函数为主体；非必要不抽取辅助函数。
- 不得在单个条件内链式调用多个接口。
- 注释只作业务占位；不得复述文档契约。

## 5. 依赖库

- 只列库名，不加任何说明。

## 6. 设计围栏

- 列出本设计有意排除的能力。
- 目的：按 YAGNI 保持设计最小、显式化未来扩展点、为评审提供具体的挑战对象。
- 条目只写设计级能力名：不带细节、不带说明。
- 条目均以否定表达开头：不支持 XXX，或类似的不做、不考虑，不寻求等表达。
- 围栏条目不得与正文已包含的能力重叠。
